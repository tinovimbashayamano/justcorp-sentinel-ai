# Step 2: Business Requirements

The JustCorp Sentinel AI platform must enable financial organisations to detect, explain, review, and report potentially fraudulent financial transactions. The system should deliver value to fraud analysts, risk officers, compliance teams, auditors, and business managers by improving the speed, consistency, transparency, and traceability of fraud-related decision-making.

## Business Requirement 1: Fraud Detection Support

The platform must assist users in identifying potentially fraudulent or suspicious transactions from transaction data. Each transaction should receive a fraud risk prediction or score so that high-risk transactions can be prioritised for investigation.

## Business Requirement 2: Explainable Fraud Decisions

The platform must provide clear and understandable explanations for fraud predictions. Users must be able to see which transaction features influenced a fraud decision so that analysts can justify, review, and document the outcome.

## Business Requirement 3: Real-Time Transaction Scoring

The platform must support real-time or near-real-time transaction scoring through an API. This will allow external financial systems to submit transaction details and receive a fraud risk assessment quickly.

## Business Requirement 4: Fraud Investigation Workflow

The platform must support a basic fraud investigation workflow where suspicious transactions can be reviewed, classified, and documented. This will help fraud analysts manage flagged cases more efficiently.

## Business Requirement 5: Audit-Ready Reporting

The platform must produce structured reports summarising fraud predictions, explanations, risk indicators, and investigation outcomes. These reports should support internal review, audit preparation, and management decision-making.

## Business Requirement 6: User Access Control

The platform must support controlled access for different user types. Fraud analysts should be able to review flagged transactions, managers should be able to view summaries, and administrators should be able to manage users and system settings.

## Business Requirement 7: Data Storage and Traceability

The platform must store transaction records, fraud scores, explanations, user actions, and generated reports. This will ensure that fraud decisions remain traceable and reviewable over time.

## Business Requirement 8: Management Insights

The platform must provide high-level fraud analytics such as total transactions reviewed, number of suspicious transactions, fraud risk distribution, and model performance summaries. These insights will help management understand fraud trends and operational risk.

## Business Requirement 9: SaaS Readiness

The platform should be designed to support future productisation. It should eventually allow multiple organisations, separate user bases, API access, and usage-based service delivery beyond a single-user academic prototype.

## Business Requirement 10: Portfolio and Demonstration Value

The platform must be suitable for presentation as a final-year AI and Machine Learning project, GitHub portfolio project, and technical interview case study. It should demonstrate machine learning, explainable AI, backend engineering, database integration, reporting, and production-oriented software design.
